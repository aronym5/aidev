Overview

A chat harness that feels like an IDE

aidev is a full-screen TUI chat harness for driving a coding model against a real project. Each conversation (“session”) lives in its own tab and can be bound to a channel — a sandboxed working directory with a shell. From that point the model can invoke tools, every call gated by the permission you grant for that turn.

Why aidev

One command center for your development

aidev is designed around a few core ideas that set it apart — everything else hangs off them.

01 / Sessions

Multi-session control center

Run several conversations side by side in tabs, each with its own prompt, history, and scroll state. Drive many agents at once without losing the thread.

02 / Sandbox

Podman sandboxing

Every session executes inside an isolated container channel. The model can run code and touch files without ever reaching your host machine. Only your shared workfolder is visible.

03 / Git & Worktrees

Parallel branches, one project

Develop several branches of the same project concurrently — across multiple sessions, containers, worktrees, and branches — without collisions. Duplicate any channel to get its own worktree-backed container.

04 / Access Control

Full access control

Choose a permission level per turn — read, write, or execute. Every tool call is gated by the permission you grant, so you always stay in control.

05 / Overview

Zoom levels for the right view

Zoom between detail, dialog, and full overview. Step back to see all sessions and channels, or dive into a single conversation — the right resolution for the task.

06 / Context

Full insight into LLM context

See exactly what the model sees and which tool calls fill its context. Full control and visibility over the context window, with manual compaction when you need to trim it.

Safety & Flexibility

Power without exposure

Every session runs in its own sandbox. A channel backs each session with an isolated working copy — either a container (podman) or a host directory (local) — so the model can act without touching your machine directly.

Flexible bridge between dialog and code. Bound sessions let the model read and write the actual codebase, run builds/tests, and show the results inline. You stay in control through permissions and a picker per turn.

podman + git integrated. Container channels isolate execution and filesystem effects; git worktrees give you a cheap, isolated copy per session/branch. The two compose — duplicate a channel to get its own worktree-backed container.

Channels

The interface to your filesystem

A channel is the interface to a filesystem and shell. Sessions without a channel are pure chat; once bound, the model can act in that working directory.

TypeDescription
podman Runs in a container. Run mode creates its own container (duplicateable per session); attach joins an existing one. Commands run as your host UID with keep-id.
local Runs directly on the host. Practical in sandboxes/CI where rootless podman is unavailable.

The status line shows a channel indicator: green = running yellow = starting red = problem grey = not checked

Permissions

You stay in control

Before sending a turn you choose a permission level (Tab cycles read → write → execute). The levels build on each other.
